### 📌 작업 개요

Vercel 배포 환경에서 이미지 로딩 지연 문제 해결. 미사용 이미지 정리, PNG → WebP 일괄 변환, Vercel 정적 자산 immutable 캐시 헤더 적용으로 이미지 페이로드를 약 63MB → 5.2MB 수준으로 축소.

### 🔍 문제 분석

- `public/assets/images` 총 63MB, 34장 raw PNG 원본
- 단일 파일 중 5.4MB(시계탑 LED 배경), 3MB(점프스케어 컷씬), 2.8MB(엔딩 캐릭터) 등 과대 용량 다수
- 모든 이미지가 압축 안 된 PNG 원본 해상도로 서빙
- `vercel.json`에 정적 자산 캐시 헤더 미설정 → 재방문/씬 전환 시마다 재다운로드
- 결과적으로 스테이지 전환 시 화면 깜빡임/지연 발생

> SSR 도입 옵션은 Vite SPA 구조상 효과 미미하고 마이그레이션 비용이 커서 본 작업 범위에서 제외.

### ✅ 구현 내용

#### 1. 미사용 이미지 정리 (-14MB)

- **파일**: `public/assets/images/` 내 PNG 6장 삭제
- **변경 내용**: 코드 어디에서도 참조되지 않는 PNG 6장 제거
- **이유**: 빌드 결과물 및 정적 자산 페이로드 축소

#### 2. sharp 기반 이미지 최적화 스크립트 추가

- **파일**: `scripts/optimize-images.js` (신규), `package.json`
- **변경 내용**:
  - `npm run optimize-images` 명령 추가
  - `public/assets/images` 하위 PNG/JPG를 WebP로 일괄 변환
  - 너비 1920px 초과 시 자동 리사이즈 (`withoutEnlargement: true`)
  - 기본 quality 85, 시각 품질이 중요한 컷씬/캐릭터(`cutscene`, `greenie_`, `jumpscare`)는 quality 92로 차등 적용
  - 변환 성공 시 원본 PNG/JPG 삭제
  - 변환 전후 용량/감소율 콘솔 리포트
- **이유**: 재현 가능한 변환 파이프라인을 코드로 박제해 향후 신규 이미지도 동일 정책으로 처리 가능

#### 3. 사용 중 이미지 28장 PNG → WebP 변환 (-89.4%)

- **파일**: `public/assets/images/*.webp` (신규 28장), `src/assets.js`, `src/routes/HubPage/HubPage.jsx`, `src/routes/TitlePage/TitlePage.jsx`, `src/stages/stage1/Stage1Placeholder.jsx`, `src/stages/stage2/Stage2Placeholder.jsx`, `src/stages/stage3/Stage3Intro.jsx`, `src/stages/stage3/Stage3Field.css`, `src/stages/stage3/Stage3Game.css`, `src/stages/stage4/Stage4Intro.jsx`, `src/stages/stage4/Stage4TimerPane.css`, `src/stages/stage4/__tests__/Stage4Intro.test.jsx`
- **변경 내용**:
  - 28장 PNG를 WebP로 변환 (49MB → 5.2MB, **-89.4%**)
  - 모든 코드 참조 경로 `.png` → `.webp` 일괄 갱신
  - JSX 인라인 `<img src>`, CSS `background-image: url(...)`, 동적 문자열 경로(`/assets/images/door_stage4.webp` 등), 테스트 fixture까지 동기화
- **이유**: 코드 참조와 실 파일 동시 갱신으로 404 누수 방지

#### 4. Vercel 정적 자산 immutable 캐시 헤더 추가

- **파일**: `vercel.json`
- **변경 내용**: `/assets/images/(.*)`, `/assets/sounds/(.*)` 경로에 `Cache-Control: public, max-age=31536000, immutable` 헤더 추가
- **이유**: 정적 자산을 1년간 브라우저/Vercel CDN에 immutable로 캐시 → 재방문 및 씬 전환 시 네트워크 요청 없이 즉시 로드

### 🔧 주요 변경사항 상세

#### `scripts/optimize-images.js`

```
- IMAGES_DIR = public/assets/images
- MAX_WIDTH = 1920
- DEFAULT_QUALITY = 85
- HIGH_QUALITY_PATTERNS = [/cutscene/i, /greenie_/i, /jumpscare/i] → quality 92
```

- ESM (`import.meta.url`) 기반, 의존성은 `sharp` 단일
- 변환 성공 시 원본 삭제, 실패 시 콘솔에 에러 출력 후 계속 진행 (한 장 실패가 전체를 막지 않음)

**특이사항**:
- 원본 PNG를 삭제하는 destructive 스크립트. 재실행 전 git working tree가 clean한지 확인 필요.
- 마스터 원본은 git history로 보존 (별도 폴더 분리 안 함).

#### `src/assets.js`

- 중앙 자산 매니페스트의 모든 이미지 경로를 `.webp`로 갱신
- 사운드 경로는 변경 없음 (사운드는 본 작업 범위 외)

#### `vercel.json`

```json
{
  "rewrites": [{ "source": "/(.*)", "destination": "/" }],
  "headers": [
    { "source": "/assets/images/(.*)", "headers": [{ "key": "Cache-Control", "value": "public, max-age=31536000, immutable" }] },
    { "source": "/assets/sounds/(.*)", "headers": [{ "key": "Cache-Control", "value": "public, max-age=31536000, immutable" }] }
  ]
}
```

- SPA fallback rewrite는 유지
- 이미지뿐 아니라 사운드도 같은 정책 적용 (사운드 파일도 immutable 자산이므로)

**특이사항**:
- `immutable` 디렉티브로 인해 브라우저가 캐시 유효성 재검증 요청도 보내지 않음. 향후 동일 파일명으로 내용을 교체할 경우 캐시 hit으로 신규 자산이 반영되지 않을 수 있음 → **파일명 변경 또는 쿼리스트링 버전 부여 필요**.

#### `src/stages/stage4/__tests__/Stage4Intro.test.jsx`

- 프리뷰 이미지 3장 (`bg_stage1_clock_example`, `bg_stage2_library_fake`, `bg_stage3_example`)의 src 단언을 `.png` → `.webp`로 갱신

### 📦 의존성 변경

- **추가 (devDependencies)**: `sharp ^0.34.5` — 이미지 변환 스크립트 전용

### 🧪 테스트 및 검증

- `npm run optimize-images` 실행 후 변환 결과 콘솔 리포트로 용량/감소율 검증
- 코드 내 모든 이미지 참조 경로가 `.webp`로 갱신되었는지 grep으로 교차 검증
  - JSX 인라인 `<img src>`, 동적 문자열 경로 (`HubPage`의 `door_stage4.webp`), CSS `background-image url(...)` 포함

- Vercel 배포 후 DevTools Network 탭에서 `Cache-Control: public, max-age=31536000, immutable` 헤더 및 재방문 시 `from disk cache` 확인 권장

### 📌 참고사항

#### 본 작업에서 제외한 항목
- **이미지 프리로드 훅 통일**: 이슈에서 제안된 "다음 스테이지 진입 직전 백그라운드 프리로딩 전략 통일"은 본 PR 범위 외. Stage 2의 부분 적용 상태 유지.
- **link rel=preload**: 첫 화면 critical 이미지 우선 로드 역시 본 작업 범위 외.
- 위 두 항목은 후속 이슈로 분리 가능.

#### 운영 시 주의
- WebP 변환 시 동일 파일명으로 내용만 교체하면 `immutable` 캐시 때문에 사용자에게 신규 이미지가 보이지 않을 수 있음. 이미지 내용 갱신 시 **파일명 변경 필수**.
- `optimize-images` 스크립트는 원본을 삭제하므로 git working tree가 clean한 상태에서 실행할 것.

#### 사전 실패 테스트
