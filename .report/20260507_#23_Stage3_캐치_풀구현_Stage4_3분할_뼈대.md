### 📌 작업 개요

PRD v6 뼈대(#20) 위에 Stage 3(캐치) 메커닉 풀 구현 + Stage 4(3분할 동시) 뼈대 + sub-stage 컴포넌트 통합 인터페이스(contract) 정의. Stage 1·2 팀 분업 진입 전 contract를 Stage 3 reference 구현으로 검증해, 후속 통합 단계에서의 리팩토링 위험을 차단.

### 🎯 구현 목표

- 단독 모드(`/stage/3`)와 3분할 모드(Stage 4의 한 칸) 양쪽에서 동일 컴포넌트가 동작하도록 sub-stage contract 합의
- Stage 3 캐치 메커닉 풀 구현 (낙하 시퀀스 · 정확도 측정 · 점수 누적 · 자동 종료)
- Stage 4 3분할 레이아웃 + 1초 합체 연출 + 점수 합산 골격 마련
- HUD/점수 누적이 Stage 3·4 결과를 정상 반영하는지 단독·3분할 모드 양쪽에서 검증

### 🔧 주요 변경사항 상세

#### `Stage3Field.jsx` — RAF 루프 + 정확도 측정
`buildSequence`로 결정적 시퀀스(연속 같은 타입 3+ 회피) 생성, 매 프레임 `topPercent`를 -10% → 110%로 보간. `→` 입력 시 캐치 존(화면 50% ± `catchZoneRatio`/2) 안의 falling 아이템 중 중심선에 가장 가까운 것을 캐치하고 `absOffset`(0~1)으로 tier 매칭. real 캐치 = tier 점수, fake 캐치 = `-50` 페널티, real 미캐치 = 0점. 종료 시 `metric = 1 - (totalPoints / maxPossible)` clamp 후 `onResult` 호출.

**특이사항**:
- 점수 누적은 `totalPointsRef`(동기 읽기) + `setScore` state(HUD 리렌더) 동시 업데이트하는 `addPoints` 헬퍼로 통일
- StrictMode 이중 실행 시 `setItems` updater 안에서 점수 누적하면 중복 적용되므로 `pointsDelta` 변수로 한 번만 반영
- `onResult`/`addPoints`는 `useCallback`으로 안정화 — 부모 리렌더 시 RAF 루프가 리셋되어 게임이 멈추는 문제 방지

#### `Stage4Host.jsx` — 결과 수집의 reference 안정성
`subResultHandlers`를 `useMemo([], [])`로 마운트 1회만 생성. 매 렌더마다 새 함수가 만들어지면 sub-stage `useEffect` deps가 바뀌어 RAF 루프가 리셋되므로 중요. 핸들러는 `prev[N] !== null ? prev : ...` 가드로 중복 호출에서도 첫 결과만 채택(StrictMode 안전).

**특이사항**:
- `Stage4Split`에 `onSubResult={ {1,2,3} }` 객체로 전달 — 함수 호출(`onSubResult(1)`) 대신 인덱스 접근(`onSubResult[1]`)이라 sub-stage가 받는 콜백 reference가 안정
- 평균 metric은 단순 `(m1+m2+m3)/3` 후 0~1 clamp → `STAGE_SCORE_TIERS[4]`로 변환

#### `sub-stage-contract.md` — 키 충돌 방지
3분할 모드는 한 키보드를 3 sub-stage가 동시에 씀. 각 stage가 자기 키만(`Stage1=←, Stage2=↑, Stage3=→`) listen하고 다른 키 무시하도록 명문화. `Space`는 호스트 시작 트리거 전용.
