# PRD v6 뼈대 구축 — 라우터 · BGM · 점수 스토어

### 📌 작업 개요

PRD가 v6로 전면 개편(1인칭 학교 호러 + 허브 + 4문 + 다단계 점수)되어 기존 PRD v4 기반 코드를 폐기하고 새 컨셉에 맞는 뼈대 구축. 각 스테이지 게임 로직은 후속 이슈에서 채울 수 있도록 placeholder + TODO 주석 처리.

**보고서 파일**: `.report/20260506_#20_PRD_v6_뼈대_라우터_BGM_점수스토어.md`

### 🎯 구현 목표

- React Router v7 기반 평탄 URL 구조 도입 (씬 스위치 폐기)
- Zustand 단일 store로 점수·진행 상태 관리
- 라우트별 BGM controller (3단 매핑: 라우트 → 트랙 ID → 파일)
- HUD 오버레이 (좌하 점수 / 우하 진행도)
- 허브 4문 PNG 버튼 + 클리어 상태 시각 반영
- 타이틀 화면에 cutscene_opening 이미지 배경 적용
- 각 스테이지 placeholder 페이지 + 모의 점수 입력 버튼 (팀원 후속 작업 진입점)

### ✅ 구현 내용

#### Phase A — 기존 코드 폐기

- **삭제**: `src/` 전체 (PRD v4 기반 IntroScene, WorldScene, BossFightScene, TenSecondsGame, ColorReactionGame, CatchGame, ParallelGame, RankingScene, NicknamePromptModal, 기존 gameStore, ranking 레이어 등)
- **이유**: PRD v6 컨셉(허브 + 4문 + 다단계 점수)이 기존 구조와 충돌, 부분 마이그레이션보다 클린 슬레이트가 부채 누적 방지

#### Phase B — 의존성 추가

- **파일**: `package.json`, `package-lock.json`
- **추가**: `react-router-dom@^7.15.0`, `zustand@^5.0.13`
- **이유**: 씬 스위치(scene 문자열 분기) 폐기 → React Router 평탄 URL 구조로 전환, Context+useReducer 대신 Zustand selector 기반 최적화

#### Phase C — 신규 뼈대 구축

##### 라우팅 (6 라우트 + 404)

- **파일**: `src/main.jsx`, `src/App.jsx`, `src/routes/RouteTree.jsx`
- **변경 내용**: BrowserRouter로 감싼 평탄 URL 구조
  - `/` → TitlePage (실 동작)
  - `/opening` → OpeningPage (placeholder)
  - `/hub` → HubPage (실 동작)
  - `/stage/:id` → StagePage (placeholder + 모의 점수 버튼)
  - `/ending` → EndingPage (placeholder + 총점 표시)
  - `/ranking` → RankingPage (placeholder + resetGame)
  - `*` → `/` 리다이렉션
- **이유**: 부스 환경 키보드 입력만 가능 → URL 가드 최소화, UI 차단 위주

##### 상태 관리 (`src/store.js`)

- **파일**: `src/store.js`
- **구성**: Zustand store + selectors + devtools 미들웨어 한 파일
  - state: `stageResults: { 1|2|3|4: { metric, score } | null }`, `hasUserStarted: boolean`
  - actions: `startGame`, `recordResult`, `clearStageResult`, `resetGame`
  - selectors: `selectTotalScore`, `selectIsStageCleared(n)`, `selectIsDoor4Unlocked`, `selectClearedCount`
- **이유**: 단일 진실 공급원 (문 클리어·총점 모두 stageResults에서 파생). selector 별도 export로 단위테스트 용이성 + 자동 리렌더 최적화

##### 점수 모듈 (`src/scoring.js`)

- **파일**: `src/scoring.js`
- **구성**: `STAGE_SCORE_TIERS` placeholder (빈 배열) + `scoreFromMetric(stageId, metric)` 순수함수
- **이유**: 시그니처 고정으로 후속 이슈에서 tier 수치만 채우면 즉시 동작. tier 비어있으면 0점 fallback으로 안전성 확보

##### BGM 컨트롤러 (`src/audio/`)

- **파일**: `src/audio/trackRegistry.js`, `src/audio/BgmController.jsx`
- **구성**: 3단 매핑 (`ROUTE_TO_TRACK` → `TRACK_TO_FILE` → 실제 파일)
  - 9개 라우트 모두 트랙 슬롯 정의, 현재는 동일 `bgm.mp3` fallback
  - `<App>` 내 `<Routes>` 밖에 1회 마운트 (라우트 전환에 영향 없음)
  - `useLocation()` 구독 + 파일 URL 동일성 검사 → 같은 파일이면 재생 유지
  - `hasUserStarted` 게이트로 autoplay 정책 회피 (타이틀 → 시작 클릭 gesture 후 첫 재생)
- **이유**: 후속 이슈에서 라우트별 신규 BGM 받으면 `TRACK_TO_FILE`만 갱신하면 끝. 현재는 모든 라우트가 같은 파일이므로 라우트 전환 시 끊김 없음

##### HUD 오버레이 (`src/components/HudOverlay/`)

- **파일**: `HudOverlay.jsx`, `HudOverlay.css`
- **구성**: 좌하 점수 / 우하 진행도, `<App>` 내 `<Routes>` 밖에 1회 마운트
  - `/` (타이틀)와 `/ranking` (랭킹)에서 자동 숨김 (HIDDEN_ROUTES Set)
  - selectTotalScore + selectClearedCount 구독
- **이유**: 점수·진행도가 라우트 전환에 영향받지 않도록 라우트 밖 배치, 의미 없는 화면(타이틀/랭킹)에서는 자동 숨김

##### 에셋 상수 (`src/assets.js`)

- **파일**: `src/assets.js`
- **구성**: `ASSETS.images.{hubCorridor, door, doorClear, cutsceneOpening}`, `ASSETS.sounds.bgm`
- **이유**: 에셋 경로를 한 군데로 모아 후속 파일명 변경 시 1곳만 수정

##### 허브 4문 PNG 버튼 (`src/routes/HubPage/`)

- **파일**: `HubPage.jsx`, `HubPage.css`
- **구성**: `bg_hub_corridor.png` 풀스크린 배경 + 4개 `<button>` + `<img>`
  - 문 1·2·3·4 모두 클리어 상태에 따라 `door.png` ↔ `door_clear.png` 동적 교체
  - 문 4번은 `disabled` + CSS `is-locked` (filter: brightness(0.35))로 어둡게 처리
  - 1·2·3 모두 클리어 시 자동 활성화
  - aria-label, focus-visible 처리로 키보드 접근성 확보
- **이유**: 부스 키보드 환경에서 진짜 `<button>` 사용해야 포커스/Enter 동작 가능

##### 타이틀 화면 cutscene_opening 배경 (`src/routes/TitlePage/`)

- **파일**: `TitlePage.jsx`, `TitlePage.css`
- **구성**: `cutscene_opening.png` 풀스크린 배경 + 검은 오버레이(45%) + 텍스트 그림자
  - 게임 제목, 스토리 한 줄, "▶ 시작", "🏆 랭킹 보기" 버튼
  - 시작 클릭 시 `startGame()` + `navigate('/opening')` (gesture 트리거 → BGM 재생 시작)
- **이유**: 부스 입장 첫인상이 검은 화면이 아닌 컷씬 분위기 이미지로 시작. 시작 버튼 클릭이 BGM autoplay 게이트를 동시에 해제

##### 스테이지 placeholder + 모의 점수 (`src/routes/StagePage/`)

- **파일**: `StagePage.jsx`, `StagePage.css`
- **구성**: `id` 검증 (`['1','2','3','4']`) + 3개 모의 버튼

- **이유**: 팀원이 게임 로직 없이도 점수 누적 흐름과 문 클리어 상태 변화를 검증 가능

### 🔧 주요 변경사항 상세

#### 폴더 구조

```
src/
├── main.jsx, App.jsx, App.css, reset.css
├── store.js                   # state + actions + selectors 한 파일
├── scoring.js                 # tier + 순수함수 한 파일
├── assets.js                  # 에셋 경로 상수
├── audio/
│   ├── BgmController.jsx
│   └── trackRegistry.js
├── components/
│   └── HudOverlay/ (jsx + css)
└── routes/
    ├── RouteTree.jsx
    ├── TitlePage/ (jsx + css)         ← 실 동작 + cutscene 배경
    ├── OpeningPage/ (jsx + css)       ← placeholder
    ├── HubPage/ (jsx + css)           ← 실 동작 + 4문 PNG 버튼
    ├── StagePage/ (jsx + css)         ← placeholder + 모의 점수 3 버튼
    ├── EndingPage/ (jsx + css)        ← placeholder + 총점 표시
    └── RankingPage/ (jsx + css)       ← placeholder + resetGame
```

**컨벤션**: 컴포넌트는 폴더 단위(.jsx + .css 짝). 데이터/순수함수 단일 파일은 `src/` 루트에 평탄.

#### 데이터 흐름

```
Stage 컴포넌트 (TODO)
   ↓ recordResult(id, metric)
store.stageResults
   ├→ HudOverlay (totalScore, clearedCount)
   ├→ HubPage (isStageCleared, isDoor4Unlocked)
   └→ EndingPage / RankingPage (totalScore)

useLocation()
   ↓
BgmController → trackRegistry → <audio src=...>
```

**특이사항**:
- `BgmController`와 `HudOverlay`는 `<App>` 내 라우트 밖 1회 마운트 → 라우트 전환에 영향 받지 않음
- 파일 URL 기준 BGM 동일성 검사 → 뼈대 단계에서 모든 라우트가 같은 파일이라 끊김 없음, 후속 단계에서 라우트별 다른 파일 들어오면 자동 hard cut
