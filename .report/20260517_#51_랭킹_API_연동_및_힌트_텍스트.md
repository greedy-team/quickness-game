### 📌 작업 개요
이슈 #51 대응. 엔딩 → 결과 등록 → /ranking 흐름을 백엔드 API와 실제 연동하고, 본인 행 자동/수동 강조, 게임 진행 힌트 텍스트, 타이틀·Stage4 UX 단순화, 오디오 컨트롤 노출 범위 제한, 정식 릴리즈 번호(v1.0.0 / build 40) 부여까지 한 묶음으로 처리.

### 🎯 구현 목표
- 엔딩 닉네임(=userId) 입력 → `POST /api/result` 등록 + 성공 모달
- `/ranking` 진입 시 `GET /api/leader-board/quickness-game` 호출, 본인 행 강조
- 본인 행 강조를 2-track 으로 제공: 엔딩 자동 매칭(nickname) + /ranking 우측 상단 ID 조회
- Vite 환경변수 접두사(`VITE_*`) 정리 + `.env.example` 제공
- 게임 진행 중 조작 안내 힌트 텍스트(스테이지별) 노출
- 타이틀/Stage4 ready 화면 톤 통일, 머지 오버레이 타이틀 제거, AudioControls는 `/hub` 에서만 노출
- 정식 릴리즈 번호(1.0.0 / build 40) 부여

### ✅ 구현 내용

#### 1) Result/Leaderboard/Users API 클라이언트 추가
- **파일**: `src/api/result.js`, `src/api/leaderboard.js`, `src/api/users.js` (+ 각 `*.test.js`)
- **변경 내용**: 모든 호출에 `AbortController` 기반 8초 타임아웃, throw 대신 `{ ok, status?, message?, ... }` 반환 패턴 채택. `VITE_API_BASE_URL` / `VITE_API_KEY` 누락 시 콘솔 에러 + 사용자 친화 메시지 반환.
- **이유**: 호출자(UI) 분기를 단순화하고, 환경 변수 누락/네트워크 오류/4xx/5xx 를 동일한 형태로 받게 해 UX 메시지를 일관 처리.

엔드포인트:
- `POST {VITE_API_BASE_URL}/api/result` — body: `{ gameName: 'quickness-game', userId, score, apiKey: {API_KEY} }`
- `GET  {VITE_API_BASE_URL}/api/leader-board/quickness-game` — resp: `{ rankings: [...] }`
- `GET  {VITE_API_BASE_URL}/api/users/{userId}` — resp: `{ ..., nickname }`

**특이사항**:
- `apiKey`는 Vite 빌드 산출물에 포함되는 공개 키 전제. 진짜 시크릿이 아닌 발급 키 가정으로, 본문에서는 `{API_KEY}` 로 마스킹.
- 응답 본문 파싱 실패 / `response.ok` 가 아닌 경우 모두 `MESSAGES.network|server|client` 로 폴백.

#### 2) 엔딩 결과 등록 흐름 — userId 입력 → 등록 → 성공 모달 → /ranking
- **파일**: `src/routes/EndingPage/EndingPage.jsx`, `EndingNicknameForm.jsx`, `RegisterSuccessModal.jsx`
- **변경 내용**:
  - phase 머신: `entered → reveal → hold → leaving → register → success → outro → /ranking`.
  - `register` 단계에서 윈도우 단축키 리스너 OFF, 폼 내부 Enter 만 submit (IME 한글 조합 중 Enter 는 무시).
  - submit 시 **`submitResult` 와 `getUserById` 를 `Promise.all` 로 병렬** 호출. 등록 성공 + nickname 조회 결과를 `myHighlight = { nickname, score }` 로 저장 후 `success` 진입.
  - `success` 모달에서 Enter/Space 또는 닫기 버튼 → `outro` → `/ranking` 으로 `state: { nickname, score }` 전달.
- **이유**: 직렬 + fire-and-forget 으로 처리할 경우, 사용자가 success → outro 로 빨리 넘어가면 nickname 조회 결과가 도착하기 전에 navigate 가 발생해 강조가 빠지는 문제가 발생. 병렬화로 outro 진입 시점에 highlight 준비를 보장.

#### 3) /ranking 리더보드 API 연동 + 본인 행 강조 (자동 + 수동)
- **파일**: `src/routes/RankingPage/RankingPage.jsx`, `RankingPage.css`, `src/routes/RankingPage/__tests__/RankingPage.test.jsx`
- **변경 내용**:
  - 마운트 시 `fetchLeaderboard()` 호출. `entries = null` (로딩) / `[]` (비어있음) / `[...]` (데이터) 3-state 분기.
  - 자동 강복귀(타이머 후 자동 이동) 제거 — 사용자가 명시적으로 Space/Enter 또는 "처음으로" 누를 때만 `/` 이동.
  - 본인 행 매칭: **manual 우선 → location.state.nickname** 순. 둘 다 **nickname 단독 매칭** (백엔드의 best-score 갱신 규칙 때문에 score 기준이 빠질 수 있음).
  - 우측 상단 ID 조회 input(form) 추가. Enter 시 `getUserById(userId)` → 응답 nickname 으로 강조 행 매칭.
  - lookup race condition 방지를 위해 `lookupCounterRef` 도입(가장 최근 요청 결과만 반영).
  - 키 단축키(`Space`/`Enter` → 타이틀)는 INPUT/TEXTAREA 포커스 중에는 무시.
- **이유**: 백엔드 응답이 userId 를 포함하지 않아 score+nickname 매칭으로 시도했으나, score 가 best-score 로 고정되어 새 기록이 갱신되지 않은 경우 강조가 빠지는 케이스가 있어 nickname 단독 매칭으로 단순화. 또한 자동 복귀가 있으면 사용자가 보드를 충분히 보지 못함.

UI 톤:
- ResultModal 톤(`#000` 배경, `#00ffcc` 네온, `Courier New`)으로 통일. 본인 행은 옅은 화이트 패널 + outline + 폰트 사이즈 살짝 증가.
- 우측 상단 input 은 RANKING 헤드라인 아래 underline-only 스타일 (border-bottom + focus 시 네온 글로우).

lookup status 메시지: `loading` / `not_found` / `error` / `탑5에 기록이 없습니다` (조회 성공했으나 표시된 entries 에 매칭이 없을 때).

### 🔧 주요 변경사항 상세

#### EndingPage 의 highlight 전달 흐름
1. `register` 단계에서 `onSubmit(userId)` 호출.
2. `Promise.all([submitResult, getUserById])` 병렬 실행.
3. 등록 OK 시 `myHighlight = { nickname, score: totalScore }` 보관 → `success` phase.
4. `success` → `outro` → `/ranking` 으로 `navigate('/ranking', { state: myHighlight })`.

#### RankingPage 의 매칭 결정 로직
```
const isMine = (entry) => {
  if (manualHighlight != null) return entry.nickname === manualHighlight;
  if (myNickname != null)      return entry.nickname === myNickname;
  return false;
};
```
- manual lookup 이 우선. 엔딩에서 강조 정보를 받았더라도, 사용자가 직접 다른 userId 를 조회하면 그쪽이 이김.
- 매칭 키 변천: `userId` (백엔드 응답 누락) → `nickname + score` (best-score 미갱신 케이스에서 누락) → 최종 `nickname` 단독.

#### result API 응답 처리
- 성공: `response.ok` (200–299) → `{ ok: true }`
- 실패: body 의 `message` 우선, 없으면 status 5xx → server fallback, 4xx → client fallback.
- 타임아웃: `AbortError` → `MESSAGES.network` + 콘솔 warn.

### 📌 참고사항
- `VITE_API_KEY` 는 클라이언트에 노출되는 발급 키 — 백엔드는 이 키 + gameName 조합으로 인증한다고 가정. 진짜 시크릿이 되어선 안 됨.
- 백엔드 응답에 `userId` 가 없는 한, 본인 행 매칭은 nickname 충돌 가능성을 가짐. 동일 nickname 다중 등록 케이스에서는 모두 강조될 수 있음(현 정책).
- AudioControls 가 `/hub` 외에서 사라지므로, 게임 중 볼륨 조정은 일시정지(허브) 동선이 전제.
- 버전 1.0.0 / build 40 으로 부여됨 — 이후 patch 는 워크플로우가 자동 증가.
- 관련 설계 문서: `docs/superpowers/specs/2026-05-17-*.md`, `docs/superpowers/plans/2026-05-17-*.md`, `docs/api-docs.json`.
