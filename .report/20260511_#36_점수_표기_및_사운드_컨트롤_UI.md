### 📌 작업 개요

이슈 #36 에 따라 두 가지 큰 흐름을 한 브랜치에 담아 구현했다.

1. **점수 표기 시스템 개선** — 현재 점수와 함께 만점·생존선(엔딩 cutoff)을 HUD/모달/엔딩 화면 전반에서 노출. 점수 막대 + 생존선 분기점 시각화, ScoreTable(점수 기준 모달), Stage 3 결과 모달 상세 breakdown, Stage 4 sub-pane 점수 합산 정책, `현재/최대` 포맷 통일, 만점 1300 → 2240 로 상향에 따른 엔딩 cutoff 700 → 1000 보정.
2. **사운드 컨트롤 UI** — `useAudioStore` (zustand + localStorage persist) 도입, `useAudioVolume` 셀렉터 훅 / `playSfx` 일회성 헬퍼 / 우상단 `AudioControls` 팝오버 컴포넌트로 BGM·SFX 볼륨과 마스터 음소거를 통합 제어. 모든 BGM/SFX 재생 지점이 store 볼륨을 구독하도록 리팩토링.

### 🎯 구현 목표

- 게임 중 어디서든 현재 점수 / 만점 / 생존선(엔딩 cutoff)을 한눈에 인지할 수 있도록 노출
- Stage 3 처럼 누적식 점수 체계도 결과 모달에서 획득 내역(breakdown)을 시각화
- Stage 4 누적 점수가 sub-pane 모달 점수의 단순 합과 일치하도록 정의 (사용자 인지와 일치)
- 우상단 단일 아이콘에서 BGM / 효과음 슬라이더와 마스터 음소거를 제공
- 설정값을 새로고침에도 유지되도록 localStorage 영속화
- 기존 모든 사운드 재생 코드(BGM 컨트롤러, 각 스테이지, 엔딩 컷씬, 다이얼로그 타이핑음 등)가 동일한 store 를 단일 진실 공급원으로 사용

### ✅ 구현 내용

#### 1. 점수 시스템 — 상수·계산 모듈

- **파일**: `src/scoring.js`
- **변경 내용**:
  - `TOTAL_MAX_SCORE` 상수 도입 — `[1,2,3,4]` 의 `maxScoreForStage` 합으로 계산되어 화면 표기와 동일한 값(현재 2240)을 단일 소스에서 제공.
  - `maxScoreForStage(4)` 를 `maxScoreForStage(1) + maxScoreForStage(2) + maxScoreForStage(3)` 로 재정의 — Stage 4 는 sub-pane 점수 합 정책이므로 stage4 tier 표(`STAGE_SCORE_TIERS[4]`)는 통계용으로만 유지.
  - Stage 3 누적 최대(`STAGE3_RAW_MAX`)는 `realCount × accuracyTiers[0].points = 400` 으로 동기화된 상수로 둠 (순환 의존 회피).
  - `ENDING_SUCCESS_CUTOFF` 를 700 → 1000 으로 상향 — 만점 변화(1300 → 1540 → 1580 → 2240) 비율 보정. 약 44.6% 라인.

#### 2. HUD — 점수 막대 + 생존선 + ScoreTable 진입

- **파일**: `src/components/HudOverlay/HudOverlay.jsx`, `HudOverlay.css`, `ScoreTable.jsx`, `ScoreTable.css`
- **변경 내용**:
  - `HudOverlay` 가 라우트별로 다른 UI 표출 — 스테이지 안(`/stage/*`)에서는 몰입 방해 최소화를 위해 간단한 `SCORE {total}` 만 표시, 그 외(허브·엔딩 라우트)에서는 막대 + 생존선 tick + 가중치 라벨 표시.
  - 점수 막대는 `(total / TOTAL_MAX_SCORE)` 비율로 채워지며, 생존선 위치는 `(ENDING_SUCCESS_CUTOFF / TOTAL_MAX_SCORE)` 백분율로 계산된 절대 tick.
  - `total >= ENDING_SUCCESS_CUTOFF` 일 때 막대 fill 클래스가 `--alive` 로 전환 — 시각적으로 "생존" 영역에 진입했음을 즉시 인지.
  - 점수 영역이 버튼(`<button>`) 으로 노출되며 클릭하면 `ScoreTable` 모달 열림 / `Escape` 키로 닫힘 / 백드롭 클릭으로 닫힘.
  - `ScoreTable` 은 Stage 1·2·3 의 tier(오차/반응/캐치 정확도) 별 점수와 가짜 캐치 페널티, Stage 4 합산 안내를 한 화면에 노출. perfect tier 는 PERFECT_HEADROOM 으로 인해 `worst ~ best` 범위 표기.

**특이사항**:
- HUD 의 `hud-overlay__weights` 영역에 `S1·2 {360} · S3 {400} · S4 {1120}` 같은 가중치 요약을 추가하여 어느 스테이지가 큰 비중인지 빠르게 알 수 있게 함.

#### 3. ResultModal — `현재/최대` 포맷 통일 + breakdown

  - `breakdown` prop 신설 — `{ label, value, delta, color }` 배열을 받아 점수 획득 내역 리스트로 렌더. Stage 3 결과 모달의 tier 별 캐치 개수, 가짜 캐치 페널티, 진짜 놓침을 보여주는 데 사용.
- **사용 지점**:
  - Stage 1 `Stage1Placeholder.jsx` 결과 화면에 `{resultScore} / {maxScoreForStage(1)}점` 적용 (immersive 결과 화면).
  - Stage 2 `Stage2Placeholder.jsx` ResultModal 에 `maxScore={maxScoreForStage(2)}` 적용.

  - 엔딩 화면 `EndingCutscene.jsx`, `EndingNicknameForm.jsx` 의 점수 라인도 `{totalScore} / {TOTAL_MAX_SCORE}` 형태로 통일.

### 🔧 주요 변경사항 상세

#### `useAudioStore` 의 store 모양

```
bgmVolume: 0.7
sfxVolume: 0.7
isMuted: false
setBgmVolume / setSfxVolume / toggleMute
```

- 값은 모두 0~1 범위(`clamp01` 으로 강제).
- `persist` middleware 가 `qg-audio` 라는 localStorage 키에 직렬화 — 새로고침/세션 재진입 후에도 사용자 설정 유지.
- 이 store 가 모든 사운드 재생 코드의 단일 진실 공급원이라, 슬라이더를 움직이는 즉시 모든 활성 오디오의 `audio.volume` 이 useEffect 구독을 통해 갱신.

#### HUD 점수 막대 산식

```
fillPct = min(100, total / TOTAL_MAX_SCORE * 100)
CUTOFF_PCT = ENDING_SUCCESS_CUTOFF / TOTAL_MAX_SCORE * 100  // 모듈 로드 시 1회
isAlive = total >= ENDING_SUCCESS_CUTOFF
```

- 막대 fill 은 `width: ${fillPct}%`, 생존선 tick 은 `left: ${CUTOFF_PCT}%` 절대 위치.
- `isAlive` 일 때 fill 색상이 `--alive` 클래스로 전환되어 시각적 통과 신호.

#### Stage 4 점수 합산 정책

- `Stage4Host` 의 `subResultHandlers` 가 각 sub-pane 의 `onResult(metric, { score })` 를 받아 `results[1|2|3]` 에 보관.
- 3개 모두 도착하면 `totalScoreRef.current = results[1].score + results[2].score + results[3].score` 로 합산하여 `onResult(aggregateMetric, { score: total })` 로 emit.
- `maxScoreForStage(4)` 가 이 정의와 동일한 합으로 계산되므로 사용자가 sub-pane 모달에서 본 점수가 그대로 Stage 4 기여분으로 누적.

#### Stage 3 breakdown 구성

`Stage3Field` 가 캐치 시점에 `statsRef` 에 누적한 `tierCounts` / `fakeCaught` / `realMissed` 를 종료 시 emit. `Stage3Game.modalProps` 에서:

```
breakdown = STAGE3_CONFIG.accuracyTiers
  .map(tier → { label, value: `${count}개`, delta: `+${count * tier.points}`, color: tier.color, count })
  .filter(row → row.count > 0)
  .map(strip count)
```

이후 `fakeCaught > 0` 이면 가짜 캐치 행(빨간색, 음수 delta) 추가, `realMissed > 0` 이면 놓침 행(회색, missScore delta) 추가.

#### AudioControls 의 외부 닫힘 로직

```
open === true 동안:
  document.pointerdown → root 바깥 클릭이면 close
  document.keydown('Escape') → close
```

`useEffect` cleanup 으로 이벤트 리스너 누수를 방지하고, `open === false` 일 땐 리스너 자체를 등록하지 않아 idle 비용 0.

### 📌 참고사항

- **점수 표시 일관성**: `현재 / 최대` 포맷은 HUD, 모든 ResultModal, 엔딩 컷씬, 닉네임 입력 폼에서 동일하게 노출. 새 사용처가 생기면 `TOTAL_MAX_SCORE` 또는 `maxScoreForStage(n)` 만 참조하면 됨.
- **엔딩 cutoff 튜닝 포인트**: `ENDING_SUCCESS_CUTOFF` 는 부스 플레이테스트 후 재조정 예정인 Tunable 값. 만점이 바뀌면 비율을 재검토해야 함.
- **사운드 store 키**: `qg-audio` (localStorage). 향후 보이스/UI SFX 등 카테고리가 늘면 store 에 키만 추가하고 `useAudioVolume(category)` 분기를 확장.
- **트랙별 scale**: 트랙별로 다른 톤이 필요하면(예: 엔딩 SFX `0.8`) `useAudioVolume(cat, { scale })` 또는 `playSfx(src, { scale })` 인수만 조정 — 사용자 슬라이더 의미는 그대로 유지.
- **접근성**: AudioControls / ScoreTable 모두 `role="dialog"` + 명시적 `aria-label` 부여. 점수 영역 버튼은 `aria-label` 에 현재/목표 점수와 통과/미도달 상태를 자연어로 포함.
- **문서 동기화**: 디자인 스펙 (`docs/superpowers/specs/2026-05-11-*.md`) 과 구현 플랜 (`docs/superpowers/plans/2026-05-11-*.md`) 이 본 브랜치에 함께 커밋되어 있음. 추후 변경 시 두 문서도 같이 갱신 필요.
