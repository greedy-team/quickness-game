## 📝 현재 문제점

- 현재 Stage 1·2는 `StagePage`에서 mock 버튼(모의 PERFECT / 모의 낮은 점수 / 결과 무효화)만 노출되어 있어, 실제 게임 메커닉이 비어 있는 상태.
- Stage 3·4는 sub-stage contract(`<StageNGame mode="standalone|split" isRunning onResult />`)에 맞춘 실 컴포넌트로 이미 마운트되어 있어, 동일한 구조로 Stage 1·2도 채워 넣어야 hub → stage → result 흐름이 완전해진다.
- 또한 Stage 4(3분할 호스트)가 4개 sub-stage를 동시에 실행하는 구조이므로, Stage 1·2가 split 모드를 지원하지 않으면 보스전이 미완성 상태로 남게 된다.

## 🛠️ 해결 방안 / 제안 기능

- Stage 1 (괘종시계 / 시계탑) — 키 바인딩: ←
  - 컨셉: 괘종 진자가 좌우로 흔들리며, 정해진 박자/타이밍에 ← 키를 눌러 맞추는 리듬·타이밍 메커닉
  - 배경: `bg_stage1_clocktower.png`
- Stage 2 (반응속도 / 교실) — 키 바인딩: ↑
  - 컨셉: 화면 신호(빛/소리/오브젝트 출현)를 본 즉시 ↑ 키를 눌러 반응 시간을 측정하는 메커닉
  - 배경: `bg_stage2_classroom.png`
- 두 게임 모두 sub-stage 통합 contract를 만족하여 Stage 4 split 모드에서도 그대로 마운트 가능해야 한다.
- 결과 산출은 metric(0=완벽, 1=최악) 정규화 규약을 따른다 (Stage 3 구현 패턴 준용).
- StagePage의 mock 버튼은 Stage 1·2 실 구현 마운트 후 제거.

## ⚙️ 작업 내용

- Stage 1 게임 컴포넌트 신규 (`src/stages/stage1/`)
  - 인트로(Space로 사용자 페이스 시작) → running → done 상태머신
  - 입력 처리: ← 키, 다른 스테이지 키와 충돌 없음 검증
  - 캐치/타이밍 판정 tier(예: 완벽 / 훌륭 / 좋아 / 통과 / 아슬) 및 점수 산정
  - 실시간 HUD (점수 / 남은 횟수 등) — Stage 3 HUD 패턴 준용
  - 한국어 라벨 가독성 (부스 환경 고려)
  - sub-stage contract 진입점 컴포넌트
- Stage 2 게임 컴포넌트 신규 (`src/stages/stage2/`)
  - 동일한 상태머신·contract 구조
  - 입력 처리: ↑ 키
  - 반응속도 측정 → metric 정규화
  - 실시간 HUD
- StagePage 정리
  - Stage 1·2 실 컴포넌트 import 및 마운트
  - 기존 mock 버튼 / 안내 문구 제거
- Stage 4 통합 검증
  - split 모드에서 Stage 1·2가 정상 동작하는지 확인
  - 키 충돌 없음 (← / ↑ / → / Space) 회귀 테스트
- 튜닝 파라미터 외부화 (`stageN.config.js`) — 난이도, 시간, 점수 tier 등
- 사운드 슬롯은 본 이슈 범위에서 제외 (후속 이슈로 분리)
