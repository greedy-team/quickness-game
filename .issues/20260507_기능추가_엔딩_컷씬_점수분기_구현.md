## 📝 현재 문제점

- 현재 `EndingPage`는 placeholder 상태(`"[Ending]"` 문구 + TODO 주석)로, PRD §5 플로우의 "엔딩 컷씬 10초" 구간이 비어 있다.
- PRD §7에는 성공 엔딩(`cutscene_ending_true.png`) / 실패 엔딩(`cutscene_ending_bad.png`)이 정의되어 있으나, 실제 운영 자산은 새로 제작된 두 이미지로 대체될 예정이다.
  - `greenie_alive.png` — 진짜 그린이가 귀신을 떨치고 도망치는 모습 (성공 엔딩 톤)
  - `greenie_silhouette.png` — 귀신이 된 그린이 단독 (실패 엔딩 톤)
- Stage 4 합체 연출(`Stage4MergeOverlay`) 직후 어떤 결과가 보이는지에 따라 점수의 의미와 재도전 동기가 결정되므로, 누적 점수 기반 분기가 필요하다.
- 부스 회전율(시간당 25~28명) 환경에서 결과 임팩트가 약하면 다음 플레이어 유도 효과가 떨어진다.

## 🛠️ 해결 방안 / 제안 기능

- Stage 4 완료(`onResult` 호출) → `/ending` 라우트 진입 시점은 기존 플로우 유지.
- `EndingPage`에서 누적 점수(`selectTotalScore`)를 기준으로 성공 / 실패 두 가지로 단순 분기.
  - 성공 — `greenie_alive.png` + 짧은 자막 (예: "진짜 그린이가 살아남았다")
  - 실패 — `greenie_silhouette.png` + 짧은 자막 (예: "또 다른 내가 되어버렸다")
- 컷오프 점수 라인은 가변(Tunable) 항목 — PRD §6 등급 컷(S/A/B/F)과 정합되도록 한 곳에서 관리.
  - 1차 기준안: 등급 S/A → 성공, B/F → 실패 (정식 컷오프 확정 후 조정)
- 컷씬은 약 10초 노출 후 자동으로 `/ranking`으로 전환(또는 키 입력 시 즉시 전환). 부스 회전율 우선.
- 분기 결과는 1회 플레이당 1장만 노출 (시퀀스 X, 단일 컷).
- 시각 연출은 단순 페이드인 + 자막 자막 1~2줄 수준에서 시작. 추후 사운드/모션 강화는 후속 이슈로 분리.

## ⚙️ 작업 내용

  - 컷오프 상수는 외부화(예: `src/scoring.js` 또는 별도 config) — 추후 등급 시스템과 공용
- 엔딩 자산 등록
  - `src/assets.js`에 `greenie_alive.png`, `greenie_silhouette.png` 등록 및 preload 대상에 포함
  - PRD §7 "확정 에셋" 섹션 갱신 (기존 `cutscene_ending_true/bad.png` → 신규 두 자산으로 표기 변경)
- `EndingPage` 실 구현
  - 누적 점수 → 분기 결정 → 해당 이미지 + 자막 렌더
  - 자막 카피 1차 안 작성 (성공/실패 각 1줄, 한국어, 부스 가독성 확보)
  - 약 10초 자동 전환 + 키 입력 시 즉시 전환 옵션
  - 페이드인 등 가벼운 진입 연출
- 라우팅 / 플로우 검증
  - Stage 4 done → `/ending` 진입 → 자동 또는 수동으로 `/ranking` 진입까지 회귀 테스트
  - `resetGame` 후 타이틀로 복귀 시 분기 결과 잔존 없는지 확인
- 튜닝 파라미터 외부화
  - 컷오프 라인, 자동 전환 지연(ms), 자막 텍스트 — 한 파일에서 조정 가능하도록 정리
- 문서 갱신
  - PRD §7 자산 표 / §6 등급 컷 메모 보강
  - 본 이슈 범위에서 사운드/보이스/모션 강화는 제외 (후속 이슈로 분리)
