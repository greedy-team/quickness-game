## 📝 현재 문제점

- Stage 1(괘종시계)·Stage 2(반응속도) 메커닉은 실 구현이 들어갔지만, 다른 스테이지 대비 BGM·효과음이 비어 있어 몰입감과 일관성이 떨어짐
- Stage 1·2 점수 로직이 다른 스테이지(특히 Stage 3·4)와 산출 기준·표기 방식이 통일되지 않아 누적 점수·보스전 연계 시 불균형 발생
- Stage 4(3분할 병렬 진행)는 뼈대가 들어간 상태이나, Stage 1·2가 채워진 지금 시점에서 sub-stage 동시 실행·키 입력 분배·점수 합산·캐치 속도 가중 등 운영 흐름에 어색한 부분이 남아 있어 손볼 필요가 있음

## 🛠️ 해결 방안 / 제안 기능

- Stage 1 사운드
  - 진자/괘종 컨셉에 어울리는 루프형 BGM 1종 등록
  - 입력 판정 tier(완벽/훌륭/좋아/통과/아슬/실패)별 효과음 슬롯 분리
  - 진입/종료 페이드 인·아웃 처리
- Stage 2 사운드
  - 교실·반응속도 컨셉에 어울리는 짧은 텐션 BGM 1종 등록
  - 신호 출현·반응 성공·반응 실패 효과음 슬롯 분리
  - 진입/종료 페이드 인·아웃 처리
- Stage 1·2 점수 로직
  - metric(0=완벽, 1=최악) 정규화 규약을 Stage 3·4와 동일 기준으로 정렬
  - tier별 점수 가중치·표기 라벨을 Stage 3·4 결과 패널과 통일
  - 누적 점수·보스전 데미지 산식에 자연스럽게 흡수되도록 환산 비율 점검
- Stage 4 병렬 진행 보완
  - 좌(Stage 1)·중(Stage 2)·우(Stage 3) 동시 실행 시 입력 분배·상태 갱신 누락 여부 점검
  - 캐치 영역 1.5배 속도 가중·점수 2배 보너스가 새 점수 체계와 정합한지 재계산
  - 3개 sub-stage 종료 타이밍 동기화(동시 종료/개별 종료 정책) 정리
  - HUD·결과 패널의 좌·중·우 점수 표기, 합산, 보너스 적용 결과 노출 일관화

## ⚙️ 작업 내용

- 사운드
  - Stage 1·2 BGM 에셋 추가 및 `trackRegistry` 등록
  - Stage 1·2 효과음 에셋 추가 및 슬롯 정의(판정 tier별)
  - 컴포넌트 마운트/언마운트 시 재생·정지 라이프사이클 연결
  - 화면 전환 시 BGM 중복 재생 방지 검증
- 점수 로직
  - Stage 1·2 metric → score 환산식 정리 및 외부화(`stageN.config.js`)
  - 결과 패널 라벨/등급 표기 Stage 3·4와 통일
  - 누적 점수·보스전 데미지 산출 회귀 테스트
- Stage 4
  - sub-stage contract(`mode="split"`) 기반으로 Stage 1·2·3 동시 마운트 재검증
  - 입력 핸들러(←/↑/→) 충돌·누락 회귀 테스트
  - 점수 2배 보너스·캐치 1.5배 속도 가중치 재적용 검증
  - 종료 동기화 정책 결정 및 결과 패널 표기 정리
