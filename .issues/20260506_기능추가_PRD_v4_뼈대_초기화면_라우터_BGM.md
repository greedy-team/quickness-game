## 본문

## 📝 현재 문제점

- PRD가 v4로 전면 개편되어 새 컨셉(1인칭 학교 호러, 허브 + 4개 문, S/A/B/F 등급)에 맞는 코드 골격이 필요함
- 한 번에 전체를 재작성하기에는 변경 범위가 크므로, 우선 진입 흐름과 공통 인프라부터 안정적으로 세워둘 필요가 있음
- 각 스테이지 구현 전에 라우팅/사운드/점수 상태 관리 같은 공통 뼈대가 먼저 자리잡아야 후속 작업이 충돌 없이 진행됨

## 🛠️ 해결 방안 / 제안 기능

- 이번 이슈에서는 뼈대(scaffold)만 구축하고, 각 스테이지 메커닉/연출은 후속 이슈로 분리
- 화면 단위 라우팅, BGM 재생 컨트롤, 점수·진행 상태 스토어를 표준화하여 후속 작업이 동일한 기반 위에서 이루어지도록 함
- 실제 게임 로직 없이도 화면 전환과 사운드, 상태 흐름이 end-to-end로 동작하는 상태를 목표로 함

## ⚙️ 작업 내용

### 1. 초기(타이틀) 화면

- PRD v4 컨셉에 맞는 타이틀 화면 신규 구성
- 게임 시작 / 랭킹 보기 등 주요 진입 버튼만 우선 배치 (실제 동작은 placeholder 가능)
- 후속 화면(허브 등)으로 라우팅되는 진입점 역할

### 2. 라우터 / 화면 플로우 뼈대

- 전체 진행 플로우(오프닝 → 허브 → 스테이지 1·2·3 → 스테이지 4 → 엔딩)에 대응되는 라우트/씬 키 정의
- 각 화면은 우선 placeholder 컴포넌트로 연결, 화면 간 이동만 동작하도록 구성
- 허브에서 1·2·3번 문 자유 선택 → 4번 문 자동 개방 흐름이 라우팅 레벨에서 시뮬레이션 가능하도록 설계

### 3. BGM / 사운드 뼈대

- 전체 구간 베이스 BGM(`bgm.mp3`) 재생 컨트롤러 구축 (재생/일시정지/볼륨)
- 화면 전환 시 BGM 유지/전환 정책 정의 (예: 허브·스테이지 공통 BGM 유지)
- 추후 스테이지별 효과음 연결을 위한 사운드 슬롯 정의 (실제 에셋은 TBD 상태로 둠)

### 4. 점수 / 진행 상태 스토어 뼈대

- 스테이지별 판정 결과(PERFECT/GOOD/FAIL) 저장 구조 정의
- 문 클리어 여부(1·2·3·4) 상태 관리
- 최종 등급(S/A/B/F) 산출 자리만 마련 (실제 산출 로직은 placeholder)
- 게임 리셋(다음 플레이어를 위한 초기화) 인터페이스 마련

### 5. 공통 UI 슬롯

- HUD 자리(좌하단 판정 표시 / 우하단 진행도 1/4~4/4) placeholder 배치
- 자막 영역 placeholder 정의

### 범위 제외 (후속 이슈로 분리)

- 각 스테이지 메커닉 실제 구현 (괘종시계, 반응속도, 캐치, 3분할)
- 오프닝/엔딩 컷씬 연출
- 1인칭 손전등 시점 등 비주얼 연출
- 실제 에셋·사운드 적용 및 밸런싱
