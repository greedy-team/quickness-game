## 본문

## 📝 현재 문제점

- PRD v6 뼈대(#20)는 완료되었으나 각 스테이지가 모의 점수 입력 버튼만 있는 placeholder 상태
- Stage 4 (3분할 동시)는 Stage 1·2·3 메커닉을 동시에 사용하는 구조라, 팀 분업 시 통합 인터페이스가 먼저 합의되지 않으면 Stage 4 통합 단계에서 큰 리팩토링이 발생할 위험
- 팀원과 병렬 작업을 안전하게 진행하려면 sub-stage 컴포넌트 contract를 미리 정의하고 한 가지 스테이지로 검증해둘 필요가 있음
- 3개 스테이지 메커닉이 들어갈 Stage 4의 3분할 레이아웃·합체 연출 골격도 함께 마련해두어야 후속 통합이 단순해짐

## 🛠️ 해결 방안 / 제안 기능

- Stage 3 (캐치) 메커닉을 풀 구현하면서, 같은 인터페이스로 Stage 4의 한 칸에 plug-in 되도록 sub-stage 컴포넌트 contract 합의
- Stage 4의 3분할 레이아웃, 마지막 1초 합체 연출 골격, 점수 합산 통합부를 먼저 마련
- 합의된 contract는 추후 팀원이 Stage 1·2를 만들 때 동일 형태로 따라 만들면 즉시 plug-in 되도록 함
- 본 이슈 완료 후 Stage 1·Stage 2 별도 이슈를 발행하여 팀원에게 분배 (이 이슈가 그 두 이슈의 선행조건)

## ⚙️ 작업 내용

### 인터페이스 설계 (선행)

- sub-stage 컴포넌트 contract 정의 (각 스테이지가 단독 화면·3분할 모두에서 동작할 수 있는 props/콜백 모양)
- 점수 보고 콜백(`onResult(metric)`) 통일
- 시작/종료 신호(외부에서 강제 종료 가능 여부, 자동 종료 시점) 정의
- 단독 모드 vs 3분할 모드 구분 prop 추가

### Stage 3 (캐치) — 풀 구현

- 진짜 기억 / 가짜 기억 아이템 정의 (PRD §7 자산 슬롯 사용)
- 방향키 입력으로 받기·피하기 메커닉
- 받은 위치 정확도 측정 (중앙 가까울수록 고득점)
- 다단계 점수 tier (`STAGE_SCORE_TIERS[3]`) 채움
- 약 30초 분량 진행 후 자동 종료 → `recordResult(3, metric)` 호출
- 단독 모드(`/stage/3`)와 3분할 모드 양쪽에서 동작 보장

### Stage 4 (3분할) — 뼈대

- 화면 3분할 레이아웃 (좌·중·우) 구성
- 각 칸에 sub-stage 컴포넌트 마운트하는 구조
- 현재는 Stage 3 컴포넌트를 한 칸에 plug-in하여 인터페이스 검증
- 나머지 두 칸은 placeholder (Stage 1·2 컴포넌트 도착 전까지)
- 3개 sub-stage 점수 합산 → `recordResult(4, metric)` 호출
- 마지막 1초 화면 합쳐짐 연출 골격 (실제 비주얼 디테일은 후속 폴리싱)
- 약 30초 분량 진행 후 자동 종료

### 통합 / 마무리

- Stage 4 placeholder 모의 버튼 제거 (실제 메커닉으로 교체)
- Stage 3 placeholder 모의 버튼 제거
- HUD 진행도 / 점수 누적이 Stage 3·4 결과를 정상 반영하는지 검증
- 단독 모드 ↔ 3분할 모드 동작 차이를 인터페이스 문서로 정리

## 🔗 후속 이슈

- Stage 2 (반응속도) — 팀원 작업, 본 이슈 완료 후 contract 확정되면 발행
