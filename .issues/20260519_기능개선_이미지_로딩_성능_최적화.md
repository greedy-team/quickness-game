## 📝 현재 문제점

- Vercel 배포 환경에서 이미지 로딩이 눈에 띄게 느림
- public/assets/images 폴더가 총 63MB, 이미지 34장으로 매우 무거움
- 단일 PNG 파일 중 5.4MB(클락타워 LED 배경), 3MB(점프스케어 컷씬), 2.8MB(엔딩 캐릭터) 등 과도하게 큰 파일 다수 존재
- 모든 이미지가 압축 안 된 raw PNG 원본 해상도로 서빙되고 있음
- 정적 자산에 대한 캐시 헤더가 vercel.json에 별도로 설정되어 있지 않음
- 스테이지 전환 시 이미지 다운로드 대기로 인한 화면 깜빡임/지연 발생
- 이미지 프리로딩이 Stage 2 한 곳에만 부분 적용되어 있고 전체 전략 부재

## 🛠️ 해결 방안 / 제안 기능

- PNG 원본을 WebP 포맷으로 변환하여 용량 60~90% 감소
- 표시 크기보다 큰 원본 이미지를 적정 해상도(예: 1920px 이하)로 리사이즈
- Vercel 정적 자산에 장기 캐시 헤더(Cache-Control: immutable) 추가하여 재방문/씬 전환 시 즉시 로드
- 다음 스테이지 진입 직전 백그라운드 프리로딩 전략 통일 적용
- 첫 화면 critical 이미지는 link rel=preload 로 우선 로드
- SSR 도입 옵션은 현재 Vite SPA 구조상 효과 미미하고 마이그레이션 비용 큼, 본 이슈 범위 제외

## ⚙️ 작업 내용

- 이미지 일괄 변환 스크립트 추가 (sharp 기반, npm run optimize-images)
- WebP 변환 후 src/assets.js 경로 일괄 갱신
- vercel.json 에 정적 이미지 캐시 헤더 규칙 추가
- 원본 PNG 마스터 보관 정책 결정 (별도 폴더 분리 또는 git history 보관)
- 변환 전후 시각 품질 확인 및 quality 값 조정
- 스테이지 진입 전 다음 씬 이미지 프리로드 훅 적용
