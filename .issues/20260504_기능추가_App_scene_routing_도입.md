## 제목

⚙️ [기능추가][App][SceneRouting] PRD §1.2 사용자 플로우 구현 (scene routing + Vite 데모 정리)

## 본문

## 📝 현재 문제점

- App.jsx가 Vite 초기 스캐폴딩(카운터 버튼, hero 이미지, Vite/React/Discord/X.com/Bluesky 링크)과 미니게임 섹션들을 한 페이지에 세로로 나열하는 개발용 데모 형태로 남아있음
- 모든 게임이 동시에 화면에 보여서 PRD §1.2의 사용자 플로우(인트로 → MG1 → MG2 → MG3 → 갑옷 장착 → MG4 → 보스전 → 엔딩)와 어긋남
- 누적 점수, 갑옷 장착 상태, 씬 전환 같은 전역 상태가 없어 보스전·엔딩 등 후속 작업의 토대가 부족
- 새 미니게임이 추가될 때마다 App.jsx에 또 한 섹션이 늘어나는 구조라 자연스럽게 정리되지 않음

## 🛠️ 해결 방안 / 제안 기능

- PRD §1.2의 사용자 플로우에 맞춰 한 번에 하나의 씬만 보여주는 scene routing 도입
- 씬 전환 컨트롤러를 App.jsx의 책임으로 통합하고, 각 미니게임 컴포넌트는 자기 씬 안에서만 동작하도록 정리
- 누적 점수와 갑옷 장착 여부 등 전역 상태를 가벼운 store(또는 Context)로 도입 (보스전 데미지 산출에 사용)
- Vite 초기 스캐폴딩(카운터 버튼, hero 이미지, 외부 SNS/문서 링크)은 제거 또는 시작 화면 등 별도 위치로 이전
- 씬 진입/종료 시 키보드 입력 클린업과 BGM/효과음 훅(차후 도입 대비) 가능한 위치 확보

## ⚙️ 작업 내용

- 씬 enum 정의: intro / minigame_1 / minigame_2 / minigame_3 / armor / minigame_4 / boss_fight / ending
- 전역 상태 store: scene, totalScore, hasArmor, bossHP (PRD §7.7 패턴 참고)
- App.jsx 씬 라우터: 현재 scene에 따라 단일 컴포넌트만 렌더
- 인트로 씬 컴포넌트 신규 작성 (시작 버튼 + 좌우 이동 튜토리얼 + 스토리 문구)
- 갑옷 장착 연출 씬 자리 마련 (실제 연출은 별도 이슈에서 구현 가능)
- 각 미니게임 종료 시 점수 누적 후 다음 씬으로 자동 전환되도록 콜백/이벤트 정리
- Vite 데모 영역 제거 또는 별도 위치 정리
- 1번/2번/3번 게임 컴포넌트의 자체 시작/재시작 사이클을 씬 라우터와 정합성 유지하는 형태로 조정
